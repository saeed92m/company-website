# UX Research — Phase 1 Baseline

## Purpose

Define the people the corporate website must serve, their likely goals, and the information architecture implications before visual design or implementation.

This is a working hypothesis baseline. It must be validated and refined as evidence becomes available.

## Primary audiences

### 1. Prospective partners and organizations
**Goals**
- Understand who the company is.
- Understand its technical domains and capabilities.
- Identify relevant collaboration areas.
- Establish credibility.
- Find a clear contact path.

**Required information**
- Company overview
- Six activity domains
- Capabilities
- Selected projects
- Founder/CEO
- Vision and development direction
- Collaboration/contact

### 2. Research and technical collaborators
**Goals**
- Determine whether the company works in a relevant scientific/engineering field.
- Understand technical interests and project direction.
- Identify a route for research collaboration.

**Required information**
- Domain pages
- Projects
- Research-oriented capabilities
- Technical profile
- Contact/collaboration

### 3. Potential clients / industrial partners
**Goals**
- Understand applicable capabilities.
- Determine whether the company can address a technical/industrial requirement.
- Initiate an inquiry.

**Required information**
- Capabilities
- Applications
- Relevant domains
- Project evidence
- Contact

### 4. Investors / strategic stakeholders
**Goals**
- Understand the company, direction, domains, and development vision.
- Assess the breadth and coherence of the technology portfolio.
- Establish contact.

**Required information**
- Company
- Vision
- Six domains
- Projects
- Development path
- Founder/CEO

### 5. General visitors / media / public
**Goals**
- Understand what the company does.
- Find reliable official information.
- Access public projects and contact information.

## Key user journeys

### Journey A — Discover company
Home → About → Fields → Vision → Contact

### Journey B — Explore a technical domain
Home/Fields → Domain → Capabilities/Applications → Relevant Project → Contact

### Journey C — Explore a project
Projects → Project overview → Status / purpose / capabilities → Contact or future project page

### Journey D — Evaluate leadership
Home/About → CEO → Professional profile → Company / Vision

### Journey E — Collaboration request
Home/Contact → Inquiry type → Form/contact mechanism → Confirmation

## UX principles

1. The user should understand what the company does quickly.
2. The six domains must be discoverable without overwhelming the visitor.
3. Technical credibility must be communicated without unsupported claims.
4. Every important informational journey should have a logical next step.
5. Contact must never be difficult to find.
6. Language switching must preserve the user's current context where possible.
7. Mobile navigation must not compromise access to any major section.
8. The interface must work naturally in both RTL and LTR.
9. Project descriptions must distinguish current status from future vision.
10. Visual design must reinforce the company's scientific/engineering identity rather than distract from information.

## Validation required later

These are hypotheses, not measured user research. Before a major redesign or expansion, validate through stakeholder review and, where practical, user testing/analytics.

## Next UX artifact

Information Architecture and sitemap, derived from these journeys.
